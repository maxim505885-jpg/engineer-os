# Local App Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox syntax for tracking.

**Goal:** One local chat/file/job/history workflow with a one-button Windows launcher.
**Architecture:** stdlib local HTTP UI + SQLite queue + single worker; wrap existing model gateway. Original files are preserved; extraction/model outputs remain unverified.
**Tech Stack:** Python 3.12+, SQLite, HTML/CSS/JavaScript; optional PyMuPDF.
**Spec:** docs/superpowers/specs/2026-10-05-local-app-design.md

## Global Constraints
- Loopback only, no proxy/redirect forwarding, no paid key required.
- 100 MiB original upload limit; candidate text 100,000 characters, PDF first 20 pages.
- Model context <=20 messages/24,000 history characters +16,000 file characters; truncation explicit.
- Model output never grants acceptance, engineering audit remains NOT_RUN.
- Source PDF verification and existing application unchanged.

## Review Focus
- Simultaneous jobs must not cross conversations or duplicate claims.
- Hostile pages must not mutate loopback data through Origin/Host/token bypass.
- Restart mid-inference must show interrupted failure without fabricating success.
- Oversized/scanned/encrypted PDF must retain original and expose extraction limitations.
- Unicode/path-like filenames and model markup must not escape storage/UI.
