# Проверяемые черновики заключений

Продолжить №10 по разрешению пользователя; №9 отложен и остаётся открытым. Расширить существующий маршрут real-case, не создавать второй источник инженерного принятия. Документ всегда является черновиком, в том числе при положительном upstream audit; финальное принятое заключение не выпускается этим модулем.

Сохранённая версия содержит текущий case ID/hash, редактируемые выводы, рекомендации и ограничения, автора записи, автоматически собранные ТЗ, исходники, факты/цитаты, нормативные/расчётные решения и замечания. Авторский текст не проверен инженерно. Неизменяемые разделы и маркировку нельзя удалить пользовательской правкой. Сохранение новой версии использует optimistic revision guard; история сохраняется в SQLite и backup.

Повторная проверка сравнивает сохранённый basis с текущим real-case, который уже проверяет исходники, ТЗ, доказательства и domain state. Устаревший/подменённый черновик нельзя экспортировать; новый черновик при BLOCK разрешён с причинами. DOCX и PDF создаются из одной проверенной структуры документа без сетевых ресурсов и без новых платных зависимостей. Экспорт не меняет принятие и не запускает FINAL AUDIT. Длинные таблицы и кириллица должны быть читаемы; отсутствующие сведения показываются явно.

Границы выпуска: только черновик, ограничения и полный след происхождения. Реальная расчётная семантика, доверенный издатель экспертного решения и принятый инженерный кейс остаются №9/12. Программный критерий №10 может быть выполнен отрицательным документом; принятие объекта не заявляется.
