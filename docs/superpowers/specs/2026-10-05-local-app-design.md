# Local ENGINEER OS workflow

User-approved goal: a free Windows local app with chat, original files, durable history and background tasks. Continue the existing engineering core; no cloud account or paid key is required. This vertical slice is an application runtime around the existing OpenAI-compatible gateway, not a replacement engineering methodology.

Use Python 3.12+ standard library HTTP, SQLite and a single background worker. Default model qwen3:8b, loopback Ollama origin http://127.0.0.1:11434. Optional Open WebUI origin and API key come from explicit environment variables; no credential is written to browser state or logs. All model traffic is loopback, without environment proxies or redirects, response size bounded to 2 MiB. No local model service available means a visible failed task, never a fabricated reply.

Serve an independent local UI on 127.0.0.1:8765. A session has immutable user/assistant messages, attached originals and jobs QUEUED/RUNNING/SUCCEEDED/FAILED. SQLite persists after restart. Claims are transactional; only one active job per conversation. An exclusive data-directory process lock prevents simultaneous startup recovery. Interrupted RUNNING jobs become FAILED after restart; queued jobs resume. Model context includes up to 20 history messages/24,000 characters and up to 16,000 file characters; actual truncation is reported. Model output is always UNCERTAINTY / NOT_EVIDENCE, acceptance=false, FINAL_AUDIT=NOT_RUN regardless of text content.

Upload TXT/MD/PDF originals up to 100 MiB; generated names in private storage, original name metadata, SHA256. TXT/MD candidate text bounded to 100,000 characters; PDF uses optional PyMuPDF, first 20 pages and same character bound. Extraction errors/encrypted/scanned PDF remain visible and original accessible. Native PDF text is explicitly incomplete/unverified and does not resolve the V4 engineering blocker. PDF extraction absence is supported without installing anything.

HTTP requests require exact server Host and same-origin Origin when present. API calls require a random per-run token supplied through the HTML bootstrap; POST missing Origin is permitted only with token for the launcher/test client. No wildcard CORS. CSP uses self-only scripts/styles; render messages with textContent. Limit bodies, reject malformed JSON, cross-session file IDs, invalid IDs, and external redirects. HTTP handles no subprocess/tool execution from model output. The loopback-only app is for a trusted single OS user; no LAN binding.

UI: session sidebar, chat, attached files, persisted job states/error messages, model connection indicator, new-session and send/upload actions. Empty/error/loading states must work; no false connected banner. Windows root Start_ENGINEER_OS.cmd discovers an available Python 3.12+ interpreter and starts the app/browser without pip installs; unsupported Python produces an actionable message. A Python CLI supports --no-browser, --port and --data-dir for repeatable checks. Closing the console stops the worker; data remains.

Verification: real SQLite persistence, concurrent claim, restart recovery, exclusive lock, original SHA/download, unavailable/malformed/redirecting model service, session isolation, hostile HTTP Origin/Host and token rejection, actual HTTP upload→queue→model→history using a clearly synthetic loopback OpenAI-compatible server, full existing suite. No claim of real qwen3 inference or Windows execution without that environment. No merge/deployment implied.
