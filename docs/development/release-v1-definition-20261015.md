Основание: пользовательский MASTER DEVELOPMENT PROMPT, AGENTS.md и полный аудит
`docs/qa/2026-10-15-full-readiness-audit.md`. Это критерии будущей приёмки, не

## Объём

Сохраняются существующий кабинет, Ollama/Qwen, SQLite/Evidence, runtime integration.
Полный инженерный профиль1.0 включает документы/ТЗ/Evidence/нормы/контрольные
расчёты/CAD/IFC/проверку/память/заключения/Windows/offline/backup. Минимальный
чат/nativePDF остаётся отдельным облегчённым профилем, а не заменой полного.
ЛИРА/SCAD расширение ведётся отдельным этапом, как разрешено MASTER§8. Когда
кейс требуетvendor results, его инженерная приёмка BLOCK до квалификации результатов.
Обязательные платные API, новая модель, новый UI или новый агентный framework не нужны.

## Контракт данных и доверия

- PROJECT/ACTUAL/MEASURED/TESTED/CALCULATED/ASSUMED/INTERPRETED/UNKNOWN различимы.
- Локальная подпись подтверждает целостность/issuer, не личность по паспорту или
  правильность измерения. Model/import JSON не может назначить себе engineering_verified.
- Review требует exact subject digest,source hashes/locators/revisions,decision,
  reviewer,method,scope/version/time. Смена любого основания аннулирует приёмку.
- Оригиналы immutable;review/transcription/conversion создают отдельные версии.
- «Не видно» не превращается в «нет». Нормативный source metadata не заменяет пункт.
- Предварительный registry arithmetic и учебный benchmark не являются приёмкой объекта.

## Проверочный corpus

Версионированный private manifest текущих29файлов;owner/backup не смешивать с
основным content. Отдельно контрольные native/scanned/mixedPDF,merged cells,
OMML,EMF/OLE passive,damaged ZIP,units/decimal signs и независимый legal IFC/DXF.
ДляV4 renderer reference заново связывается с текущими DOCX bytes;старые534pages
можно использовать только при подтверждённой истории соответствия. Полнота
измеряется по объектам/ячейкам/числам, не weighted-token recall одному.

## Пять сквозных отказов для обязательного review

1. Изменение оригинала/правила/review после ACCEPTED немедленно делает case/report/knowledge stale.
2. Прерванный worker не оставляет RUNNING как завершённый и не удваивает принятое содержание.
3. Крупный/вредоносный Office/CAD/IFC не исчерпывает память и не запускает OLE/macros/network.
4. Ровный текст скрывает ошибку знака/десятичной запятой/единицы/merged cell — сравнение обязано её выявить.
5. Обновление кода/зависимостей/ключа не теряет данные и не сохраняет недействительную приёмку.

## Базовый выпуск и полный запрошенный объём

12release gates определяют базовый инженерный выпуск1.0. Это не отменяет ранее
запрошенное закрытие всех восьми направлений. Для заявления «весь исходный объём
готов на100%» дополнительно должен быть завершёнV01в заявленном vendor scope:
ЛИРА — полная проверяемая цепочка исходных данных/результатов, SCAD — подтверждённое
исследование API/export и совместимости без обещания неподтверждённой функции.
Если vendor-проверки нужны управляющемуТЗ или реклама включает их поддержку,
соответствующая готовность остаётся BLOCK до фактических receipts. Решение выпустить
базовую версию раньше не закрываетV01и не выдаётся за закрытие всей задачи.
