## Порядок работ — зависимости и критерии завершения

### P0. Управление источником истины и незакрытые дефекты (№1/3/10/12/13)
1. Сверить актуальный candidate SHA, все открытые PR, required checks и пересечения веток; не смешивать draft PR102 (R4) с релизом.
2. Разобрать реальный DOCX-run с 1492 receipts (1491 COMPLETED + 1 RUNNING), 1496 model calls и 749/749 batches; построить детальную корреляцию receipt_id/batch/call/restart. Установить причину первого FAILED14505/14684; если данные недостаточны — классифицировать UNKNOWN, а не «исправлено».
3. Воспроизвести выявленную проблему на минимальном регрессионном сценарии; исправить без изменения доказательной/acceptance границы; проверить restart/cancel/crash/resume, SQLite consistency, один вызов модели ↔ устойчивый журнал.
**Gate P0:** ни один незавершённый receipt не считается COMPLETE; reconciled manifest + CI + реальный повторный probe; оригинал/хеш неизменны.

### P1. Производственная полнота документов (№13, главный активный этап)
1. Для реальных DOCX и V4 вести source-bound coverage по страницам/логическим частям, включая графические source ids, OCR и геометрию. Пересчитывать после parser/renderer изменения.
2. Проверить raster/mixed tables: grid, объединённые ячейки, значения, подписи, связь с соседним текстом на квалифицированной выборке реальных страниц. Невосстановленные ячейки и конфликты маркировать UNKNOWN/BLOCK.
3. Проверить Word/EMF placement/rendering, подписи/легенды/схемы; отдельно отображать unsupported commands. Word/PDF layout не объявлять эквивалентным без визуальной сверки.
4. Сопоставить 41 OMML формулу с источником визуально, не вычислять и не проверять математическую корректность.
5. Разрешить OCR native-vs-raster конфликты (40 V4 native-text-empty страниц и иные сложные страницы) с exact character/cell/graphic evidence и provenance. Не считать OCR-кандидатов подтверждёнными фактами.
6. Прогнать квалифицированный multi-document корпус: native/scanned/mixed PDF, DOCX, XLSX и реальные отчёты. Сделать risk-based coverage и машинный evidence register; фиксировать все неизвестные области, без искусственных PASS.
**Gate P1:** 100% заявленного source scope имеет подтверждённую или явно unavailable/uncertain обработку; критические mixed tables, подписи, формулы и OCR локаторы сверены по оригиналу с актом; полный Store/model/receipt replay без расхождений. №13 не закрывать одним счётчиком страниц.

### P2. Инженерный контур без новых расчётов (№5/6/7/8/14)
1. Для доступного ТЗ сверить requirement→source→fact→finding→conclusion; определить фактическую область обследования.
2. Проверить актуальность и применимость норм на документальном уровне (edition, clause, scope, evidence), не выдумывать нормативы.
3. Провести отрицательные и доступные положительные *документальные* кейсы, отрабатывая статусы PASS/WARNING/UNCERTAINTY/BLOCK.
4. Реальный инженерный ACCEPTED №14 возможен только после полного доказательного комплекта и квалифицированной проверки, в том числе расчётной, если она требуется ТЗ. Пока расчёты отложены, отсутствие такого кейса не блокирует P1/P3.
**Gate P2:** воспроизводимый протокол с проверкой ТЗ, статусов и FINAL AUDIT; №14 открытым, пока нет положительной реальной приёмки.

### P3. Пользовательские функции и интеграция (№11/15/16/17/18)
1. Проверить один сквозной маршрут: оригинал→задание→извлечение→доказательство→черновик→исправление→повторный аудит→история/restore.
2. Память: ACCEPTED-only gating, версионность/отзыв и защита от stale; тестовые fake-positive сценарии не выдавать за инженерную базу знаний.
3. Заключения: ссылочность таблиц/графики/формул и редактируемый DOCX/PDF, без автоматического повышения статуса.
4. CAD/DWG: провести отдельную проверку ограничений конвертера/лимита 15906 объектов, unit/geometry identity и roundtrip прежде чем объявить соответствие. Расчётные модели сюда не возвращать.
5. Multi-AI: бесплатный Ollama/Open WebUI primary, альтернативные адаптеры optional; единые cost-free fallback/identity/error/receipt rules.
**Gate P3:** e2e CI/браузер/Windows runner с верифицируемыми источниками и отсутствием потери данных; реальные acceptance caveats задокументированы.

### P4. Установка, эксплуатация и выпуск (№9/12/19)
1. Только после устойчивых P0–P3: clean Windows install с одной кнопкой, доступная локальная модель, отсутствие обязательных платных ключей; обновление/перезапуск и выключение ПК.
2. Backup/restore и аварийный restart на ПК пользователя; сравнение hash оригиналов, DB/schema migration, rollback.
3. Security, architecture, dependency, core tests, Windows, браузер, real corpus, документация, release checklist.
4. Main/tag/release и объявление «готово» только после выполнения требуемых gates, в том числе №14, если он остаётся обязательным выпускным критерием.
**Gate P4:** физически проверенная установка + выпускной audit, никаких необоснованных инженерных ACCEPTED.
