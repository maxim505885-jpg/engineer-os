# Заголовки и продолжения таблиц Docling

## Подтверждённая проблема

В сохранённом диагностическом экспорте V4 для страницы 397 была полная сетка
12×4. Изображение показывало продолжение таблицы: первая строка содержит данные,
а локальный заголовок отсутствует. Адаптер использовал эту строку как заголовок
и выдавал только последующие строки. В последнюю строку экспорта также попали
подписи нижнего штампа. Проверка числа ячеек этого не обнаруживала.

## Поведение после исправления

- Сохраняется существующая проверка полной сетки и единственной страницы таблицы.
- Для обычной таблицы требуется булево `column_header` на каждой ячейке:
  первая строка полностью размечена как заголовок, остальные — как данные.
- Отсутствующие, частичные, многорядные или повторяющиеся заголовки дают BLOCK.
  Заголовки продолжения не подставляются из соседней страницы без отдельной
  проверяемой связи с источником. Первая строка данных не отбрасывается молча:
  весь такой диапазон блокируется, исходный PDF и диагностический экспорт остаются.
- Две или более разные известные подписи штампа (`№ док.`, `Подп.`, `Кол.уч`,
  `Изм.`) внутри обычной таблицы дают BLOCK. Это консервативный сигнал для
  визуальной проверки, а не универсальный детектор штампов. Корректная таблица,
  содержащая эти подписи как данные, тоже потребует проверки.
- Узкое существующее распознавание отдельного нижнего штампа сохраняется.
- `inspect_docling_tables.py` сохраняет все поля ячеек, включая `column_header`
  и `bbox`; отсутствующие поля не восстанавливаются предположениями.
- Версия batch-проверки повышена до 5: результаты с audit версии 4 не считаются
  актуальными. Для выборочной повторной обработки используйте новый каталог,
  чтобы сохранить старые результаты для сравнения.

Разметка заголовка от модели не доказывает правильность содержания. Полная сетка
и успешная нормализация по-прежнему требуют визуальной и смысловой сверки.

## Что реально проверено

Сохранённый экспорт страницы 397 теперь блокируется с причиной смешения штампа,
вместо выдачи 11 строк с ошибочными заголовками. Исторический экспорт страницы 15
сохранил верные значения, но не содержит `column_header`: его нельзя использовать
для доказательства работы нового gate. Нужен новый диагностический экспорт или
полный исходный Docling export с настоящей разметкой; добавлять флаги вручную ради
PASS нельзя.

Unit-тесты используют синтетические таблицы и проверяют отсутствие молчаливой
потери строк, сохранение строк при полной разметке, блокировку смешанного штампа,
сохранение метаданных диагностики и отказ от устаревшего cache. Свежий OCR V4
в этой среде не выполнен: Docling не установлен, Windows checkout недоступен.
Evidence Register, Supabase и ACCEPTED не изменяются.

## Выборочная проверка на Windows

Из checkout новой ветки сначала проверьте именно Python проекта:

```powershell
.\.venv\Scripts\python.exe -c "import sys, docling; print(sys.executable); print(sys.version); print('DOCLING_LOCAL_OK')"
```

Если импорт успешен и исходный PDF имеется, выполните сначала одну страницу:

```powershell
.\.venv\Scripts\python.exe .\scripts\inspect_docling_tables.py .\.engineer-os\v4-drive-source.pdf --page 397 --sha256 b5d95b660b35bfb6b2441623635cba91c235efd754bc283dfe1405f075834916 --output .\.engineer-os\v4-header-recheck\table-page-397.json
```

Это диагностический экспорт, не принятое доказательство. Сверьте разметку,
первую и последнюю строки, границы основной таблицы и штамп с исходником.
Затем проверьте страницу 15 тем же скриптом с `--page 15` и другим именем
выхода. Не запускайте все 534 страницы до проверки этих двух примеров.

Документация upstream о булевом поле `TableCell.column_header`:
https://docling-project.github.io/docling/reference/docling_document/#docling_core.types.doc.document.TableCell
