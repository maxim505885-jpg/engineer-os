Статус: исследование официальных GitHub-репозиториев и документации, сопоставленное с ENGINEER OS. Новые зависимости в этом шаге не установлены; интеграция, Windows-проверка новых компонентов и инженерная квалификация не выполнены. №13 остаётся открытым; №14/19 также без изменения.

Проверенный кандидат: integration/release-candidate-v1, 1a765fa1766add7b5c5950a98893cd6e8099c6f8. Состояние до исследования: §133 карты. Исследование не возобновляет ЛИРА/RES.

## Резерв Word и отклонённые ожидания

[ONLYOFFICE/DocumentServer](https://github.com/ONLYOFFICE/DocumentServer), AGPL-3.0: резерв для полноценного встроенного просмотра/редактирования DOCX и второго независимого renderer. Community и платные редакции различаются. Это дополнительный серверный компонент; включать только если измеримый результат оправдывает размер установки и поддержку. Совпадение с исходным Word не гарантируется.

[VolodymyrBaydalka/docxjs](https://github.com/VolodymyrBaydalka/docxjs): возможный быстрый HTML preview. Upstream прямо отмечает ограничения HTML, отсутствие поддержки Word fields/TOC и динамического разбиения на страницы. Поэтому не выбирать как доказательство полного Word rendering/покрытия.

## Последовательность внедрения

1. Интегрировать проверенные способы визуального чтения Word в штатный Store/Worker/API/UI: точный исходный OMML, производный preview, связанные processed bitmap/WDP descriptors, источник и шрифты/версия конвертера. Исходник read-only; макросы/OLE не активировать; лимиты и остановка дерева процессов обязательны.
2. Сначала проверить PP-StructureV3 и img2table на сохранённых проблемных областях V4, сравнить с существующими native/Tesseract/Docling кандидатами. Выбрать один полезный дополнительный маршрут по содержательному приросту и потерям, времени/RAM, русскому тексту и Windows. GMFT рассматривать отдельно для native таблиц.
3. При полезности внедрить PDF.js для просмотра/поиска/сверки исходника. Сохранить связь file SHA→page→bbox→result и неизменность оригинала. Новые распознавания не превращать автоматически в accepted evidence.
4. DWG: продолжать существующий LibreDWG→производный DXF→ezdxf маршрут; явная ведомость неподдержанных объектов, слоёв, размеров, единиц, xref и текста. Сначала квалификация реального чертежа; не смешивать это с отложенными расчётами.
5. Desktop pywebview после устойчивого текущего web приложения. Продолжать существующий Windows/bootstrap/backup/CI маршрут.

Все выбранные маршруты предполагают локальное исполнение, заранее скачанные модели и локальные assets, без обязательного платного API. Лицензия библиотеки не заменяет проверку лицензии моделей, транзитивных зависимостей и условия распространения итогового продукта.

## Критерий результата

Нужна не установка большого списка библиотек, а воспроизводимая сверка исходника: где получен текст/значение, к какой ячейке/подписи/единице оно относится, какие части пропущены и где читатели расходятся. Для Word — формулы, графика, поля, шрифты и порядок; для PDF — raster/mixed tables и графические подписи; для CAD — геометрия и потери конвертации. Полнота на представительном корпусе и квалифицированная инженерная проверка остаются отдельными критериями №13. Исследование репозиториев не закрывает №13, не устанавливает обновление на пользовательском ПК и не создаёт ACCEPTED-кейс.

Официальные README и страницы лицензий проверены 11.10.2026 через GitHub plugin и первичные web-источники. Upstream main/master может изменяться: перед добавлением зависимости зафиксировать конкретный релиз/commit, веса, хеши и совместимость с установленной версией Python.
