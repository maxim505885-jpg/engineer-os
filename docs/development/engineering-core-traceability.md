# Связка требования → роль → источник

В CORE_RUN создаётся неизменный preliminary снимок engineering_review. Наблюдение роли может содержать text, source_ids, requirement_ids и relation (SUPPORTS/CONTRADICTS/UNKNOWN). ID требований берутся из переданного текущего ТЗ, ID источников — из разрешённого контекста. Без явной привязки требование не считается рассмотренным.

Связанный источник должен быть кандидатом с действующим source review и исходной идентичностью. Ссылка на файл сама по себе не устанавливает основание наблюдения. SOURCE_CONFIRMED относится к цитате/расположению, а не к инженерной истине или классу данных. Имя автора review заявлено пользователем и не аутентифицировано.

Сверка блокирует непокрытые требования, UNKNOWN/CONTRADICTS, разные заявленные отношения и неподтверждённые источники. Она не угадывает смысл противоречий по свободному тексту. Промежуточные ответы автоматического анализа имеют собственные sticky gates, независимо от сводки; ссылки на журнал и SHA сохраняются. Изменение ТЗ/источника во время выполнения прекращает сохранение завершённого черновика. Новое ТЗ после выполнения не переписывает исторический снимок.

Результат находится в «Профильный анализ → Сверка требований и ролей». Завершено выполнение ≠ завершена экспертиза. Даже SOURCE_LINKED сохраняет UNCERTAINTY, engineering_verified=false и FINAL AUDIT NOT_RUN. Кейс/QC учитывает BLOCK этой сверки. Проверки норм и solver не заменяются матрицей.
