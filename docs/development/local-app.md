# Локальный кабинет ENGINEER OS

В корне проекта дважды нажмите **Start_ENGINEER_OS.cmd**. Он выбирает Python 3.12+ из окружения проекта, `py -3` или `python`, запускает локальный сервер и открывает браузер. Python 3.13/3.14 пользователя подходят. Платный ключ, облачная база и установка новых репозиториев для этого режима не нужны. При первом запуске модель должна уже работать в Ollama: по умолчанию `qwen3:8b`, `127.0.0.1:11434`.

Кабинет: `http://127.0.0.1:8765`. Новый диалог → прикрепить TXT/MD/PDF при необходимости → написать вопрос → отправить. Отмеченные файлы включаются в контекст очередного сообщения. История, задачи и оригиналы сохраняются в `.engineer-os/local-app/` и остаются после перезапуска. Для остановки закрыть окно консоли или нажать Ctrl+C. Не удалять папку данных ради обновления кода. Один экземпляр использует одну папку данных; второе окно сообщит, что она занята.

При отсутствии модели кабинет открывается, но показывает отсутствие связи. Отправленная задача завершится ошибкой; историю и файлы это не удаляет. После запуска Ollama можно отправить сообщение снова. Индикатор доступности проверяет список моделей, а не качество ответа. Ответы — непроверенный контекст, не доказательства: UNCERTAINTY, NOT_EVIDENCE, acceptance=false, FINAL AUDIT NOT_RUN. SUCCEEDED означает, что ответ получен и сохранён. Инженерный CORE и его evidence/acceptance gates не заменены.

## Файлы и память

Оригиналы до 100 MiB сохраняются отдельно с SHA256 и доступны для скачивания. TXT/MD читаются как UTF-8; PDF — опциональным PyMuPDF. Если PyMuPDF отсутствует, файл защищён паролем, повреждён или является сканом без native text, оригинал сохраняется, текст отмечается недоступным. Этот кабинет не запускает OCR/Docling. Для PDF берутся кандидаты только из первых 20 страниц, максимум 100,000 символов: рисунки, таблицы и полнота не подтверждены. Проверка V4 по исходным картам остаётся отдельной работой.

В запрос модели входит до 20 последних сообщений в пределах 24,000 символов и до 16,000 символов выбранных файлов. Ограничения контекста видны на карточке задачи. История хранится целиком; интерфейс показывает последние 200 сообщений и задач, до 200 файлов на диалог и последние 500 диалогов. Это дисковая история/контекст, не подтверждённая инженерная память или обучение модели.

## Настройки и проверяемый запуск

```bash
python scripts/run_local_app.py --no-browser --port 8765 --data-dir /absolute/private/data
```

`ENGINEER_OS_LOCAL_MODEL_URL` — loopback origin Ollama/Open WebUI без пути (HTTP), `ENGINEER_OS_LOCAL_MODEL` — ID модели из сервиса, `ENGINEER_OS_LOCAL_MODEL_KEY` — ключ Open WebUI, если нужен. `ENGINEER_OS_LOCAL_PROVIDER` — `ollama` по умолчанию или `openwebui`. Для Open WebUI задать provider `openwebui`, затем URL `http://127.0.0.1:8080` и его API key. Ключ остаётся на сервере; UI его не получает. Windows `.env` автоматически не читается: не считать прежний OAuth/token подтверждением соединения. Default идёт напрямую в Ollama через существующий OpenAI-compatible gateway.

Кабинет слушает только 127.0.0.1, проверяет Host/Origin и токен текущего запуска, не разрешает wildcard CORS. Транспорт модели не использует env proxy и не следует redirects. Локальный HTTP не предназначен для LAN или нескольких недоверенных пользователей. Модель не запускает команды, браузерные действия или сторонние навыки. Сторонние интеграции и Browser Use остаются отдельными, явно включаемыми инструментами.

Проверки: `python -m unittest discover -s tests`, `node --test tests/dashboard_counts.test.cjs`, `node --check engineering/local_app/ui/app.js`. HTTP-тесты используют синтетический OpenAI-compatible сервис на loopback, настоящий HTTP, SQLite и исходные байты файла. Они не подтверждают реальное qwen3 inference, качество анализа, Windows или Open WebUI. Эти проверки отдельно фиксируются в карте проекта.

Маршруты Open WebUI сверены с [официальной документацией](https://docs.openwebui.com/reference/api-endpoints/): `/api/models` и `/api/chat/completions`; для Ollama используется `/v1`.

[Фактическая проверка локального сценария](local-app-verification-2026-10-05.md). DOM integration в `e2e/local_app_dom_smoke.cjs` использует jsdom 26.1.0 только для разработки; кабинет не зависит от Node/jsdom. `e2e/local_app_ui_smoke.cjs` — отдельная будущая проверка с установленным Playwright/Chromium.

В одном диалоге можно сохранить до 200 вложений. Следующая загрузка явно отклоняется; создайте другой диалог. Все принятые вложения доступны для выбора и скачивания.
