# Локальный кабинет ENGINEER OS

В корне проекта дважды нажмите **Start_ENGINEER_OS.cmd**. Он выбирает Python 3.12+ из окружения проекта, `py -3` или `python`, запускает локальный сервер и открывает браузер. Python 3.13/3.14 пользователя подходят. Платный ключ, облачная база и установка новых репозиториев для этого режима не нужны. При первом запуске модель должна уже работать в Ollama: по умолчанию `qwen3:8b`, `127.0.0.1:11434`.

Кабинет: `http://127.0.0.1:8765`. Новый диалог → прикрепить TXT/MD/PDF при необходимости → написать вопрос → отправить. Отмеченные файлы включаются в контекст очередного сообщения. История, задачи и оригиналы сохраняются в `.engineer-os/local-app/` и остаются после перезапуска. Для остановки закрыть окно консоли или нажать Ctrl+C. Не удалять папку данных ради обновления кода. Один экземпляр использует одну папку данных; второе окно сообщит, что она занята.

При отсутствии модели кабинет открывается, но показывает отсутствие связи. Отправленная задача завершится ошибкой; историю и файлы это не удаляет. После запуска Ollama можно отправить сообщение снова. Индикатор доступности проверяет список моделей, а не качество ответа. Ответы — непроверенный контекст, не доказательства: UNCERTAINTY, NOT_EVIDENCE, acceptance=false, FINAL AUDIT NOT_RUN. SUCCEEDED означает, что ответ получен и сохранён. Инженерный CORE и его evidence/acceptance gates не заменены.

## Файлы и память

Оригиналы до 100 MiB сохраняются отдельно с SHA256 и доступны для скачивания. TXT/MD читаются как UTF-8; PDF — опциональным PyMuPDF. Если PyMuPDF отсутствует, файл защищён паролем, повреждён или является сканом без native text, оригинал сохраняется, текст отмечается недоступным. Этот кабинет не запускает OCR/Docling. Для PDF берутся кандидаты только из первых 20 страниц, максимум 100,000 символов: рисунки, таблицы и полнота не подтверждены. Проверка V4 по исходным картам остаётся отдельной работой.

В запрос модели входит до 20 последних сообщений в пределах 24,000 символов и до 16,000 символов выбранных файлов. Ограничения контекста видны на карточке задачи. История хранится целиком; интерфейс показывает последние 200 сообщений и задач, до 200 файлов на диалог и последние 500 диалогов. Это дисковая история/контекст, не подтверждённая инженерная память или обучение модели.

## Настройки и проверяемый запуск

```bash
python scripts/run_local_app.py --no-browser --port 8765 --data-dir /absolute/private/data
```

`ENGINEER_OS_LOCAL_MODEL_URL` — loopback origin Ollama/Open WebUI без пути (HTTP), `ENGINEER_OS_LOCAL_MODEL` — ID модели из сервиса, `ENGINEER_OS_LOCAL_MODEL_KEY` — ключ Open WebUI, если нужен. `ENGINEER_OS_LOCAL_PROVIDER` — `ollama` по умолчанию или `openwebui`. Для Open WebUI задать provider `openwebui`, затем URL `http://127.0.0.1:8080` и его API key. Ключ остаётся на сервере; UI его не получает. Windows `.env` автоматически не читается: не считать прежний OAuth/token подтверждением соединения. Default идёт напрямую в Ollama через существующий OpenAI-compatible gateway.

Кабинет слушает только 127.0.0.1, проверяет Host/Origin и токен текущего запуска, не разрешает wildcard CORS. Транспорт модели не использует env proxy и не следует redirects. Локальный HTTP не предназначен для LAN или нескольких недоверенных пользователей. Модель не запускает команды, браузерные действия или сторонние навыки. Сторонние интеграции и Browser Use остаются отдельными, явно включаемыми инструментами.

Проверки: `python -m unittest discover -s tests`, `node --test tests/dashboard_counts.test.cjs`, `node --check engineering/local_app/ui/app.js`. HTTP-тесты используют синтетический OpenAI-compatible сервис на loopback, настоящий HTTP, SQLite и исходные байты файла. Они не подтверждают реальное qwen3 inference, качество анализа, Windows или Open WebUI. Эти проверки отдельно фиксируются в карте проекта.

Маршруты Open WebUI сверены с [официальной документацией](https://docs.openwebui.com/reference/api-endpoints/): `/api/models` и `/api/chat/completions`; для Ollama используется `/v1`.

[Фактическая проверка локального сценария](local-app-verification-2026-10-05.md). DOM integration в `e2e/local_app_dom_smoke.cjs` использует jsdom 26.1.0 только для разработки; кабинет не зависит от Node/jsdom. `e2e/local_app_ui_smoke.cjs` — отдельная будущая проверка с установленным Playwright/Chromium.

В одном диалоге можно сохранить до 200 вложений. Следующая загрузка явно отклоняется; создайте другой диалог. Все принятые вложения доступны для выбора и скачивания.

## Подготовка инженерной проверки локально

Выберите «План проверки по ТЗ», отметьте сохранённые оригиналы, введите ТЗ в поле задания и отправьте. Фоновый worker вызывает существующий ENGINEER CORE без обращения к модели: планирует проверку отчёта, норм и обязательный FINAL AUDIT. В карточке задачи раскройте план: видны оригиналы с SHA256, непроверенные статусы и недостающие этапы. План и ТЗ сохраняются между запусками. Наличие файла не подтверждает его полноту или пригодность и не создаёт evidence ID. Все специалисты NOT_RUN, UNCERTAINTY, acceptance=false.

Чат не становится ТЗ автоматически: этот режим выбирается явно. API допускает inspection/report/normative/calculation/final_audit через requested_checks; специалистам задания пока не исполняются. Прежняя SQLite-база расширяется без удаления истории. Проверка Windows и живой qwen3 оставлена на последний этап; подготовка CORE доступна без Ollama.

## Локальный реестр кандидатов

Раскройте «Реестр · непроверенные кандидаты». Выберите оригинал этого диалога, укажите страницу для PDF, точную цитату и вашу запись/интерпретацию. TXT/MD не имеют номеров PDF-страниц. При сохранении сверяются байты и SHA256 оригинала, затем точное совпадение цитаты с UTF-8 текстом или native текстом указанной PDF-страницы, включая страницы за пределами первых 20. Несовпадение отклоняется. Скан, защищённый/повреждённый PDF или недоступный parser дают NOT_CHECKED, с явной необходимостью проверки.

Записи сохраняются в SQLite, до 500 на диалог, видны после повторного открытия. Всё остаётся UNVERIFIED, acceptance=false и FINAL AUDIT NOT_RUN. MATCH означает только совпадение текста. Координаты фрагмента, полнота источника и инженерная достоверность ещё не подтверждены. Показанная цитата пользователя при NOT_CHECKED — его заявление, не извлечённый факт. Эти ID принадлежат локальным кандидатам и не передаются как accepted evidence в CORE/Supabase. Класс данных по умолчанию U; API допускает P/F/M/T/C/A/I/U, но data_class_verified всегда false. Подтверждение кандидатов, OCR и исполнение специалистов ещё не реализованы.

## Координаты цитат и проверка происхождения

Для native PDF цитаты сохраняются области поиска PyMuPDF в points от верхнего левого угла страницы без её поворота, вместе с page_rotation. UNIQUE допускается только для одного точного вхождения (включая перекрывающиеся), одного найденного прямоугольника и точного совпадения get_textbox этой области с цитатой; повторы/многострочный фрагмент дают AMBIGUOUS, отсутствие geometry — NOT_LOCATED. До 100 областей сохраняются, UI показывает первые 10. TXT/MD — NOT_APPLICABLE, без придуманных страниц или координат. Старые записи без provenance остаются доступными.

Только UNIQUE создаёт частичный NormalizedDocument с реально извлечённой цитатой/областью, затем существующие evidence_candidates и validate_evidence_candidate проверяют связь source hash/block/page. document_validation.VALIDATED имеет scope=SOURCE_BINDING_ONLY. Это не полная нормализация PDF, не OCR, не проверка факта или инженерное принятие. Профильные проверки и evidence acceptance остаются невыполненными. Идентификатор этого DI-кандидата не передаётся в accepted gate.

Система координат сверена с [официальной документацией PyMuPDF](https://pymupdf.readthedocs.io/en/latest/page.html). Геометрия поиска — область native текста, не подтверждённая область таблицы/рисунка.

## Просмотр страницы с областями цитаты

На PDF-кандидате нажмите «Посмотреть страницу». PNG показывает исходную страницу с красными рамками найденных областей; при AMBIGUOUS это кандидатные области, не подтверждённое единственное место. Если областей нет, показывается страница без выдуманной подсветки. Оригинальные PDF-аннотации сохраняются в рендере. Подсветка не подтверждает факт/вывод; записи остаются UNVERIFIED.

Перед каждым просмотром повторно сверяются принадлежность диалогу и SHA256 оригинала/кандидата. PNG не длиннее 1601 пикселя по любой стороне, до 10 MiB; одновременно до двух рендеров. PDF decoding complexity и жёсткий общий deadline этим не ограничены. Рисование происходит в памяти, оригинал на диске не меняется. Учтены повороты и смещённый CropBox. Просмотр закрывается при смене диалога, устаревший ответ не открывает прежнюю страницу; poll списка не удаляет изображение. Ошибочный/защищённый PDF или отсутствие PyMuPDF дают видимую ошибку с возможностью скачать оригинал.

Это функция просмотра, не сохранённая ручная верификация. Реальный браузер/layout/CSP и Windows пока не проверены; DOM smoke проверяет HTTP PNG→FileReader→image src и изоляцию, Python — пиксели рамки и сохранность исходника.
