## Порядок продолжения

1. Повторить регрессию 225ee83, отделив сохранённые CI receipts от нового локального результата. Сверить актуальную документацию; исправлять конкретные воспроизводимые сбои.
2. T03: диагностировать подготовленный LibreOffice сначала на собственном TXT/DOCX. Требовать реально созданный читаемый PDF; exit 0 и --version недостаточны. После рабочего normal control квалифицировать Windows isolation. Пользовательские файлы до квалификации не открывать движком.
3. T04: связать renderer reference с текущими оригиналами; сверить все обязательные таблицы, формулы, графику и критические числа, полноту ТЗ. Невыясненные места сохранять BLOCK/UNCERTAINTY.
4. T06: обычный интерфейс выбора source-bound правила и просмотра нормы/факта; предметное подтверждение редакции, применимости и вывода. Не подменять полные нормы метаданными.
5. T07–T09: расширять только заявленную численную/CAD/IFC квалификацию; для больших DWG сначала bounded census, затем явный loss ledger. Повреждённый экспорт не принимать.
6. T10/T11: пройти реальный scoped case→приёмка→память→FINAL DOCX/PDF с текущими источниками и ответственным reviewer. Затем T12/T13: поставка, обновление/откат/перезагрузка, финальная проверка и выпуск.

ЛИРА saved results через испытанный vendor API остаются недоступны; IFC/SCAD в переданном комплекте отсутствовали при последней сверке. Код не может заменить недостающие расчётные результаты или ответственное инженерное решение. До предметной проверки эти ограничения не закрываются.

Пользовательский каталог, текущая ветка, сервер и оригиналы сохраняются. Платные сервисы не добавляются. Следующий программный приоритет — T03; установка Xiaomi не является его зависимостью.
