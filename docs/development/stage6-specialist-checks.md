# Пункт 6А — контракты и предметные блокировки, 06.10.2026

Продолжение утверждённого плана, пункт 6 «Довести профильные проверки». Этот подэтап не закрывает пункт 6. Цель — исключить обход входных контрактов и показывать пользователю и контролю качества основания, которые не может подтвердить модельный черновик.

## Сделано

- Нормативная цепочка: неверные скаляры/строка вместо массива ID/неограниченные значения блокируются. Полная цепочка по-прежнему только READY_FOR_EXPERT_VERIFICATION, не принятие нормы.
- Расчётный intake: только типизированные CalculationArtifact/CalculationArtifactRole; ограниченный комплект; повторная валидация каждого артефакта; неизвестная роль не может обеспечить готовность.
- `numeric_comparison.compare_quantity`: самостоятельный арифметический примитив Decimal с явной таблицей единиц (длина, сила, давление, площадь, безразмерные). Перевод в SI до сравнения; несовместимая размерность, неизвестная единица, нечисловые/неограниченные значения и неподдержанный оператор дают BLOCK. Арифметическое совпадение/несовпадение остаётся UNCERTAINTY: ни истинность исходного значения, ни применимость нормы не проверены. Этот примитив пока не подключён к фактам или UI/API; автоматическое извлечение чисел из текста не добавлено.
- В CORE_PLAN/CORE_RUN сохраняется `specialist_checks`: для запрошенных normative/calculation явные непроверенные prerequisites. Solver NOT_RUN/NOT_CONFIGURED означает состояние маршрута приложения, не утверждение, что программа нигде не установлена. `command -v lira/scad` не нашёл команд в PATH; диски пользователя Windows не проверялись.
- Эти блокировки передаются каждой роли, включая предварительную финальную сверку, сохраняются после перезапуска и видны в UI. CORE_RUN и итоговый engineering_status не скрывают предметный BLOCK за завершённым черновиком. Ошибка исполнения остаётся отдельно от доказанного дефекта объекта; engineering acceptance=false и FINAL AUDIT NOT_RUN.
- Identity продолжения включает новые модули предметных проверок.
