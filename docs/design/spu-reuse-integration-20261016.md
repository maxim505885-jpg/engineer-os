## Схема интеграции

1. Интерфейс СПУ служит основой рабочего стола, навигации и карточек проекта.
   Существующие проверенные формы ENGINEER OS используются внутри этих разделов:
   источники/ТЗ,сверка Evidence,нормы,расчёты/CAD/IFC,итог,память и настройки.
2. Данные рабочего стола поступают из существующих authenticated API ENGINEER OS.
   Статические показатели и статусы из скриншотов не копируются как реальные.
   Workspace/session не объявляется автоматически обследованным физическим объектом.
   Реестр объектов СПУ требует отдельного отображения/переноса с происхождением.
3. Electron-оболочка СПУ адаптируется к scripts/run_local_app.py и его фактическому
   loopback origin/build identity. Сохраняются отдельное окно,трей,один экземпляр,
   память окна,журнал и остановка только своего дочернего сервера. Старые Flask
   API не имитируются вторым runtime. Существующий webview остаётся совместимым
   способом запуска до квалификации Electron-поставки.
4. Исходная SQLite platform.db и ENGINEER OS Store не объединяются копированием.
   Сначала описывается схема переноса; импортированный отчёт/вердикт/урок получает
   источник и неподтверждённый статус. SOURCE_CONFIRMED/ACCEPTED/FINAL_AUDIT не
   выводятся из надписей старого интерфейса. Этот проход не мигрирует рабочую базу.
5. Из СПУ повторно используются прикладные модули только после адресной проверки
   их контрактов: шаблон отчёта,каталог дефектов,структура разделов,роли и извлечение.
   LIR-эвристики,проверка ГОСТ по15формальным признакам и повторяемость DWG-размеров
   не подменяют существующие инженерные проверки. Автопринятие и вымышленные
   измерения не переносятся.

## Обязательные технические границы

- Подключение к серверу проверяет идентичность сборки/данных; текст заголовка HTML
  или занятый8765 не являются доказательством нужного backend. Чужой процесс не
  останавливается. Рабочие данные исходной СПУ и ENGINEER OS сохраняются.
- Существующие token/origin/CSP проверки,source hashes,job limits,verification
  issuer и зависимости нормативных/инженерных решений остаются действующими.
- Визуальный перенос заменяет inline handlers и сторонние font requests на
  совместимые с действующей CSP/offline реализации. Данные выводятся безопасно.
- Electron: contextIsolation=true,nodeIntegration=false,ограниченный preload;
  IPC проверяет sender,навигация ограничена нужным origin,внешние URL проверяются.
  Подключение облака,подписок или отправка рабочих данных не включаются автоматически.
- Не копируются node_modules,дистрибутивы,кэши,platform.db,секреты и рабочие материалы
  в Git. Источники переносимых файлов и изменения фиксируются по SHA.

## Пакеты реализации и критерии

A. Перенести утверждённую визуальную оболочку СПУ,подключить рабочий стол к
   существующим данным и сохранить действующие формы. Проверки: пустой/заполненный
   проект,реальные счётчики,сохранение черновиков,desktop/mobile,клавиатура,CSP.
B. Адаптировать готовый Electron launcher и preload к ENGINEER OS без второго
   backend. Проверки: занятый чужой порт,запуск/повторный запуск/выход,свой процесс,
   origin/IPC,окно/трей и запуск с отдельной тестовой базой.
C. Сопоставить функции и данные СПУ с инженерными контрактами ENGINEER OS;
   подготовить адресный импорт без автоматического доверия старым заключениям.
D. Повторить существующие browser/regression сценарии,собрать кандидат Windows
   и проверить offline/backup/update/rollback. Установщик1.2.0 СПУ не является
   автоматически новым дистрибутивом ENGINEER OS.

Пункт2 остаётся отложенным пользователем. Предыдущие реализованные пакеты не
отбрасываются. Данный документ не означает завершение интерфейсного переноса,
запуск готового Electron,миграцию данных или приёмку реального объекта.
