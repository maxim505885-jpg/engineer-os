# ENGINEER OS — результаты ЛИРА 2024 (R4)

1. Распакуйте архив в новую папку.
2. Откройте в ЛИРА нужную задачу с сохранёнными результатами. Для первой проверки используйте «секция 2 прогибы.lir».
3. Запустите `START.cmd` из полученного архива (в репозитории ему соответствует `RESULTS.cmd`) и выберите тот же `.lir`.
4. Дождитесь окончания. Откроется папка на рабочем столе. Пришлите `RESULT_SUMMARY.json` и все `part_*.zip` из этой папки. Если вместо сводки появился `RESULT_ERROR.json`, пришлите его.

Расчёт не запускается. Таблицы модели читаются из отдельной копии; исходный файл не сохраняется и не перезаписывается. Хеш оригинала сравнивается до и после чтения. Копия остаётся в выходной папке, чтобы не удалить файл, который могла оставить открытым ЛИРА.

## Что извлекается

- Таблицы исходной модели — отдельный ZIP, тот же проверенный reader V3.
- Основные перемещения и усилия от загружений, нагрузки на фрагмент и продавливание: контекст `shape=0`, `history=0`, `SuperElement=0`.
- Доступные массивы частот, периодов, собственных значений и модальных параметров.
- Общие количества узлов/КЭ/историй из RES API; совпадение количеств — проверка согласованности, не доказательство связи с моделью.
- Для РСН, РСУ и армирования — проверка доступности API, без полного числового экспорта.

По каждой величине сохраняются номер узла/КЭ, реальный номер загружения, сечение, метод API, значение либо ошибка. Единицы берутся из описаний установленного API и сохранены в `api-contract.json`; значения не пересчитываются по настройкам интерфейса ЛИРА.

## Статусы

`PARTIAL_RESULT_EXPORT`: числовые значения получены, полнота ещё не подтверждена.

`RESULT_ACCESS_UNAVAILABLE` / `NO_NUMERICAL_VALUES_EXPORTED`: API не предоставил числовые результаты. Это не доказательство их отсутствия в модели.

`BUDGET_EXHAUSTED`: достигнут лимит; сводка показывает, какие категории прочитаны. Сохранённые данные остаются доступными.

`SOURCE_CHANGED`: хеш исходника изменился во время работы; связь выгрузки с выбранной версией требует повторной проверки.

`RESULT_EXPORT_FAILED`: маршрут не завершился; точная ошибка находится в JSON.

## Границы

R4 не извлекает все истории, динамические формы, суперэлементы, варианты РСН/РСУ и армирования. `shape=0/history=0` — явно выбранный основной контекст, не все формы. Нагрузки на фрагмент и продавливание — результатные величины, не полный перечень приложенных нагрузок исходной схемы. Вспомогательные жёсткости КЭ57 и полные исходные нагрузки остаются отдельной задачей.

RES API выбирает задачу по имени. Поэтому даже совпавшие количества не подтверждают идентичность модель→результаты→завершённый расчёт. Инженерная корректность и приёмка не объявляются.

Значения записываются потоком. Файл содержит до 50 000 строк, ZIP-часть — до 40 файлов данных и 80 МиБ данных. По умолчанию лимит значений — 50 млн запросов и 1 ГиБ TSV; `MaxBytes` ограничивает именно TSV, а не весь пакет. Отдельные пределы: исходник 512 МиБ, таблица 128 МиБ, все таблицы 512 МиБ, метаданные входной модели 16 МиБ. Для максимальных параметров (2 ГиБ TSV) зарезервируйте 6 ГиБ свободного места: копия, таблицы, TSV и их ZIP сохраняются отдельно; достижение лимита отражается в отчёте. Отсутствующее или ошибочное значение не заменяется нулём.

Выходная папка должна быть на локальном диске; сетевой или перенаправленный рабочий стол не поддерживается. В таком случае укажите локальный `OutputRoot`, например `C:\LiraExports`.

Командный запуск для диагностики:

```powershell
.\RESULTS.ps1 -ModelPath 'C:\path\model.lir' -OutputRoot 'C:\path\exports' -NoExplorer
```

Нужны установленная ЛИРА SAPR 2024, её COM-компоненты и 64-битный Windows PowerShell. Дополнительные платные API, Python или отдельный компилятор не требуются.
